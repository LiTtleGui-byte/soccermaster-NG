# SoccerMaster 每日实验日志

这里按日期记录实际研究过程，方便回顾决策、查找证据，以及整理周报、论文和答辩材料。

它与其他目录的分工如下：

| 位置 | 用途 |
| --- | --- |
| `lab_notes/` | 按时间记录做了什么、为何这样做、观察到什么 |
| `reports/` | 原始日志、JSON、HTML、图片和其他机器证据 |
| `REPRODUCTION_STATUS.md` | 当前 Gate 和项目状态的唯一权威账本 |
| `experiments/` | 实验代码、配置、消融设计和研究入口 |

## 日期与目录

- 文件名统一使用 UTC 日期，格式为 `YYYY-MM/YYYY-MM-DD.md`。
- 不同主机或日志采用其他时区时，在正文保留原始时间和时区。
- 同一天只有一个主日志文件；继续工作时在对应小节追加，不另建 `final`、`new` 等副本。

```text
lab_notes/
├── README.md
├── template.md
└── 2026-08/
    ├── 2026-08-13.md
    ├── 2026-08-14.md
    ├── 2026-08-15.md
    └── 2026-08-16.md
```

## 记录规则

1. 只记录真正执行过的操作；计划命令必须标注“尚未执行”。
2. 每个重要结论尽量链接到 `reports/`、代码、manifest 或状态账本。
3. 不粘贴大段重复日志；保留关键退出码、核心数字和证据路径即可。
4. 必须区分已确认、推断、未知和风险。
5. 失败也要记录，包括直接错误、未到达的阶段和是否发生 fallback。
6. 不记录密码、token、私钥、认证文件内容或其他秘密。
7. “后续计划与候选方向”可以有多项，不代表已经批准执行。

## 建议使用方式

- 实验结束后：补充一条时间线和结果摘要。
- 每个工作日结束前：写“一句话总结”和“可用于写作的素材”。
- 更新 Gate 结论时：先检查原始证据，再同步 `REPRODUCTION_STATUS.md`；不能只改每日日志。
- 写周报或论文时：从日志定位关键数字，再回到原始报告复核。
