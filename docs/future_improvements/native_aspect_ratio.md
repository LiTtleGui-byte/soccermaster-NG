# 保持长宽比的多分辨率视觉输入

## 状态

- 当前状态：`待研究`
- 优先级：基线复现之后
- 当前不修改训练代码，不改变论文基线配置

## 研究动机

足球转播视频通常接近 `16:9`。当前预训练流程最终把不同长宽比的画面统一拉伸到 `512×512`，可能造成球场线、球员外形和运动几何关系的形变。

目标不是简单地把所有输入改成固定 `16:9`，而是在可控计算量下尽量保留裁剪区域的长宽比，并让视觉编码器和各空间任务头正确处理矩形 patch 网格。

## 已确认的当前行为

1. 训练时的几何增强顺序为：随机仿射、随机透视、随机裁剪、最终 resize。
2. 随机裁剪的高度比例和宽度比例分别从 `[0.6, 1.0]` 采样，因此裁剪后的长宽比不固定。
3. `KEEP_ASPECT_RATIO=False`，最终所有输入都会被强制 resize 为 `512×512`。
4. SigLIP2-large 使用 `patch16`，正方形输入产生 `32×32=1024` 个 patch。
5. 检测、球场线、关键点和相机任务头目前使用 `sqrt(L)` 恢复空间网格，隐含了特征图为正方形的假设。
6. 检测视频逐帧调用 transform，而 `ClearAugmentationMetas` 会在每次调用时清除已保存的随机参数。按当前代码路径推断，同一段视频的不同帧可能没有共享几何增强参数；这一点需要用最小运行测试确认。

## 推荐方向

采用“视频级一致增强 + 保持比例 + patch 对齐的分辨率分桶 + 固定 token 预算 + 二维位置编码插值”。

### 1. 视频级一致增强

同一段视频的 30 帧共享一次随机裁剪、仿射、透视、翻转和颜色增强参数，避免人为制造帧间抖动。

### 2. 更可控的随机裁剪

不再分别独立采样裁剪高度和宽度。候选方式是采样裁剪面积和长宽比，例如：

```text
裁剪面积：原图的 60%～100%
裁剪比例：4:3～2:1
```

具体范围需要根据训练数据的真实分辨率分布确定，不能直接视为最终超参数。

### 3. 分辨率分桶

将比例相近的样本放入同一个尺寸桶，并让每个桶的 patch 数大致相同。以下只是保持约 1024 个 patch 的候选示例：

| 近似比例 | 输入尺寸（高×宽） | Patch 网格 | Patch 数量 |
|---|---:|---:|---:|
| 1:1 | `512×512` | `32×32` | 1024 |
| 4:3 | `448×576` | `28×36` | 1008 |
| 16:9 | `384×672` | `24×42` | 1008 |
| 2:1 | `352×704` | `22×44` | 968 |

同一个 batch 只包含同一尺寸桶的样本，避免第一版实现复杂的跨样本 token packing。

`288×512` 可作为低成本诊断实验，但它只有 `18×32=576` 个 patch，与 `512×512` 基线的计算量和空间信息量不同，不能单独用于判断长宽比是否带来提升。

### 4. 空间位置编码

保留现有 SigLIP2-large 的可学习绝对位置编码，并根据实际 patch 网格进行二维 bicubic 插值：

```text
原始：[32×32, 1024]
16:9 桶：[24×42, 1024]
```

插值后的空间位置编码继续参与训练。只要帧数仍为 30，时间位置编码不需要插值。

第一版不把绝对位置编码替换成 2D-RoPE，以保持对现有 SoccerMaster checkpoint 的兼容性和实验可比性。

### 5. 显式传递空间形状

Backbone 输出中增加真实空间形状：

```text
local_features: [B, T, L, D]
spatial_shape:  (Hp, Wp)
```

所有空间任务头使用 `(Hp, Wp)` 恢复特征图，不再通过 `sqrt(L)` 假设正方形。

## 预计影响范围

- 数据增强：视频级随机参数、裁剪策略、resize 和分桶采样器。
- SigLIP2 embedding：矩形 patch 网格和二维位置编码插值。
- SoccerMaster 时间注意力：支持不同批次使用不同的 `L`，同一视频内保持一致。
- 检测头：显式接收空间形状。
- 球场线与关键点头：支持矩形特征图和矩形目标热图。
- 相机标定头：检查相机内参与 resize、crop、padding 的一致变换。
- Batch/collate：按尺寸桶组 batch；若未来加入 padding，需要同时传递有效区域 mask。
- Checkpoint：记录输入策略、桶配置和位置编码初始化方式。

## 分阶段实验

### E0：原始基线

保持现有 `512×512` 流程，完整复现论文结果。

### E1：只修复视频增强一致性

仍使用 `512×512`，只保证同一视频的 30 帧共享增强参数。用于判断当前逐帧随机增强是否影响时间建模。

### E2：固定 16:9 诊断实验

使用固定 `288×512` 或相同 token 预算的 `384×672`，验证矩形网格、位置编码和任务头的数据流是否正确。这不是最终方案。

### E3：保持比例的分辨率分桶

启用多个 patch 对齐的尺寸桶，与 E0/E1 在相同数据、随机种子和训练预算下对比。

### E4：架构级原生多分辨率（远期）

只有 E3 显示稳定收益后，再评估 SigLIP2 NaFlex、2D-RoPE 或类似 Qwen-VL 的 token packing。该阶段会改变 backbone 和 checkpoint 兼容性，应作为独立研究分支。

## 评价指标

- 检测：人员检测 mAP、召回率，重点观察小目标与画面边缘目标。
- 球场线和关键点：原有指标，并单独检查几何一致性。
- 相机标定：标定误差及不同镜头比例下的稳定性。
- 视频语义与解说：原有分类、检索或生成指标。
- 效率：每步耗时、峰值显存、每帧 patch 数和吞吐量。
- 稳定性：是否出现 shape、padding、mask 或 checkpoint 加载错误。

## 未决问题与风险

1. 训练数据真实长宽比分布尚未统计，分桶范围不能提前定死。
2. 矩形输入对球场线、关键点热图和相机内参的影响需要逐项验证。
3. 位置编码插值能否充分适应宽于预训练网格的输入，需要实验确认。
4. 多尺寸 batch 可能降低数据加载效率，并增加分布式采样复杂度。
5. 如果同时改变长宽比和 patch 数，实验结论会混入计算量变化。
6. 原生 NaFlex 或 2D-RoPE 更灵活，但会降低与原始 SoccerMaster 基线的直接可比性。
