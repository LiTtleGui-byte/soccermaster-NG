# 检测、足球小目标与跨帧跟踪

## 状态

- 当前状态：`待研究`
- 优先级：`P1`
- 进入条件：人员检测基线和评估协议已经复现

## 当前行为

- 论文配置主要检测 person，`DETR_DETECT_BALL=False`。
- 检测头使用每帧局部特征，并把 `B×T` 合并后逐帧检测。
- 当前配置为 300 queries、0 层 DETR encoder、1 层 decoder、1 个注意力头和1个特征层级。
- 检测头本身不保证同一球员在相邻帧具有同一身份。

轻量配置可能是有意的计算折中，不能在没有基线结果时直接判定为缺陷。

## 改进方向

### 1. 足球小目标检测

足球是传球、射门和控球理解的重要线索。候选实验：

- 启用 person + ball 两类检测。
- 单独报告 ball AP、recall 和漏检率。
- 使用更高分辨率或保留长宽比的输入。
- 引入多尺度局部特征。
- 调整 query、匹配代价和小目标采样策略。

进入实验前先确认训练数据中球的标注覆盖率和一致性。

### 2. 检测头容量消融

逐项比较，避免同时改变多个因素：

```text
decoder：1 → 3 → 6 层
attention heads：1 → 4 或 8
feature levels：1 → 多尺度
local features：early / late / both
```

每项同时报告准确率、显存、吞吐和训练稳定性。

### 3. 跨帧关联

第一阶段不修改检测器，只在检测后加入关联：

```text
检测框
+ ReID embedding
+ 相邻帧位置和运动约束
→ track ID
```

第二阶段再研究时间 query 或时序检测头，使检测和跟踪联合训练。

### 4. 为其他任务提供结构化信息

稳定的球员和足球轨迹可以进一步服务于：

- 球员重识别。
- 球权和动作识别。
- 战术分析。
- 解说生成中的事实约束。

这属于后续跨任务研究，不能提前耦合进人员检测基线。

## 最小实验顺序

1. 复现 person-only 检测指标。
2. 统计球标注并可视化随机样本。
3. 在固定小数据集上启用 ball 类别。
4. 对检测头容量做单变量消融。
5. 使用已有检测与 ReID 输出尝试离线关联。
6. 最后考虑端到端时序检测和跟踪。

## 评价指标

- Person AP、ball AP、recall 和每类错误数量。
- 小目标、遮挡目标和画面边缘目标的分组指标。
- Tracking 的 HOTA、IDF1、ID switches 等指标。
- 每帧耗时、显存和视频吞吐量。

## 风险

- 足球尺寸极小且可能严重模糊，标注质量决定可达到的上限。
- 增大检测头会提高多任务训练成本。
- 单帧检测误差会在跟踪中累积。
- 如果视频增强不一致，任何时间关联实验都不可信。
