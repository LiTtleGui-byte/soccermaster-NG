# 统一评估与错误分析协议

## 状态

- 当前状态：`待研究`
- 优先级：`P0`
- 目标：让不同实验可以公平比较，并能解释模型为什么变好或变差

## 每次评估必须记录

```text
代码提交或工作区状态
配置文件和命令
Python及关键依赖版本
checkpoint来源与哈希
数据版本、split和样本数
随机种子
输入尺寸、帧数和采样方式
推理与解码参数
硬件、耗时和峰值显存
```

## 固定评估层级

### L0：静态与单元测试

检查 shape、mask、坐标变换、checkpoint 加载和参数覆盖。

### L1：固定单样本

每个任务保存少量不会变化的诊断样本，输出中间张量统计与可视化。

### L2：固定小规模评估集

用于快速比较改动，样本列表和顺序固定，不从完整验证集临时随机抽样。

### L3：完整验证/测试集

只对通过 L0～L2 的方案运行，并保留完整预测文件。

## 任务指标

- 检测：按类别、目标尺寸、遮挡和画面位置分组。
- 线/关键点/标定：除平均指标外，按镜头类型和长宽比分组。
- ReID/跟踪：身份准确率、ID switches 和轨迹完整性。
- 解说：文本指标、事件准确率、事实一致性和人工抽样。

## 错误样本记录

每项实验至少保存：

- 最好样本。
- 最差样本。
- 基线正确但新方法错误的回归样本。
- 基线错误但新方法修复的样本。
- 输入、标注、预测和必要的中间可视化。

解说任务的建议错误类型：

```text
事件完全错误
动作细节错误
角色或球队错误
结果错误
合理但参考文本措辞不同
语言不完整或重复
无视觉依据的幻觉
```

## 可重复性

- 验证集默认不 shuffle。
- 生成评估默认使用确定性解码；随机生成单独报告。
- 指标脚本对同一预测文件重复运行应得到相同结果。
- 报告均值时同时保存逐样本结果，便于后续审计。

## 完成标准

- [ ] 每个任务有固定的小规模诊断集。
- [ ] 指标脚本输入输出格式明确。
- [ ] 所有论文指标均能从保存的预测文件重新计算。
- [ ] 失败样本可以回溯到原始输入和配置。
